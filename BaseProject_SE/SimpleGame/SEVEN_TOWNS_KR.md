# 일곱 마을 오픈월드 확장 명세

기준: 2026-10-26, 기존 중세 암흑시대 2.5D RPG의 연장선.
이 문서는 이전 문서의 3개 소규모 거점·18명 기본 주민 설정을 대체한다.

## 이번 구현 범위

- 7개의 고정된 마을과 그 사이의 연속된 야외 지역. 입장 키나 화면 전환 없이 걸어서 이동한다.
- 마을 하나는 3×3 청크, 폭 2,304 월드 단위다. 기존 (0,0), (1,0), (0,1)의 작은 마을은 첫 마을의 구역에 포함된다.
- 초기 기본 주민은 마을마다 30명, 총 210명. 기존 플레이어의 죽음으로 태어난 전승자는 이 인원에 추가하며 지우지 않는다.
- 모든 주민은 고유한 주택 주소와 집을 가진다. 휴식·부활은 자기 집 문 앞에서 한다.
- 편지의 출발·이동·도착, 전달된 정보를 이용한 이사, 이동 중 저장/복원을 구현한다.
- 지형의 기존 청크 스트리밍과 원점 재배치를 유지한다. 7개 마을 바깥에서도 지형 생성이 이어진다.
- 행성 단위의 좌표 구획과 지역별 SQLite 저장을 추가했다. 2.5D 지면 렌더링과 7개 마을을 유지하며, 구형 행성·우주 이동·무제한 개체 시뮬레이션은 후속 범위다.

## 마을 배치와 이동 시간

현재 캐릭터의 지면 이동 속도는 초당 190 단위이며 `TownWorld::PlayerSpeed`로 공유한다.
인접한 마을 중심은 5청크 = 3,840 단위 떨어져 있다.
**마을 중심 사이**는 직선으로 약 20.21초다. 마을 경계 간 빈 공간은 2청크 = 1,536 단위로 약 8.08초다.
길 우회·전투·정지·달리기는 이 시간에 포함하지 않는다.
이는 모든 마을 쌍을 20초로 만든다는 뜻이 아니다. 도로망에서 이웃한 마을 사이의 간격이다.

| 번호 | 마을 | 중심 청크 | 주요 환경 |
|---|---|---|---|
| 1 | 재의 안식처 | (0,0) | 비교적 안전한 시작 마을 |
| 2 | 황동 장터 | (5,0) | 상업 중심 |
| 3 | 검은 나루 | (10,0) | 낮은 치안, 약탈 성향 주민에게 매력적인 환경 |
| 4 | 푸른 수림 | (0,5) | 안전과 학습이 균형 잡힌 환경 |
| 5 | 흰 종 수도원 | (5,5) | 학습과 깨달음 중심 |
| 6 | 붉은 철벽 | (10,5) | 상업과 긴장이 공존 |
| 7 | 먼별 초원 | (5,10) | 외곽의 정착지 |

```text
재의 안식처 ─ 황동 장터 ─ 검은 나루
    │           │           │
푸른 수림   ─ 흰 종 수도원 ─ 붉은 철벽
                │
             먼별 초원
```

M으로 마을 목록을 열고 1~7로 목적지를 선택한다. 상단에 화면 방향에 맞춘 안내와 중심까지의 직선 이동 예상 시간이 표시된다.
M에서 0을 선택하면 원정 또는 가까운 마을 안내로 돌아온다. Q는 레벨 2 원정 기록이다.
키 안내나 HUD 외에 마을 이름을 지형 위에 크게 그리지 않는다.

## 주민과 주택

### 초기 배치와 전승

새 기본 주민은 사냥꾼·상인·구도자·약탈자를 섞어 배치한다. 기존 주민은 직업·재산·체력·전승 이력을 유지한다.
첫 마을로 기존 18명의 기본 주민을 통합하고 부족한 기본 인원을 추가한다. 전승자는 가까운 마을에 배정한다.
마을의 최초 인원은 30명이지만 이사와 새로운 전승으로 실제 인원은 달라진다. 정확히 30명으로 강제하기 위해 주민을 삭제하거나 복제하지 않는다.

기본 주민 1~18의 ID와 전승자 `18 + lifeId`는 보존한다. 새 기본 주민 ID는 별도의 높은 예약 구간을 사용한다.
로드 때 이미 존재하는 전승자의 집과 마을을 출생지로 되돌리지 않는다.

### 집의 배치

- 주택은 9개 구역에 분산한다. 구역마다 중앙 십자 도로를 비우고 양옆의 고정 필지에 집을 놓는다.
- 초기 주택은 구역별로 먼저 한 채씩 배정하여 한곳에 몰리지 않게 한다.
- 주민마다 `(마을, 필지 번호)`가 고유하다. 중앙 예배당과 겹치는 필지는 제외한다.
- 72개 필지 이후에는 외곽 고리로 확장해 전승자에게도 별도의 주소를 줄 수 있다.
- 이사 중에는 기존 집을 유지하고 도착할 마을의 빈 필지를 예약한다. 도착해야 소속과 집 주소가 바뀐다.
- 이사 완료 후 기존 집의 Actor는 새 주소로 옮겨지거나, 해당 지역이 로드되지 않았다면 제거된다. 주민 기록은 계속 남는다.
- 집 문 앞에서 E를 누르면 집 번호·주인·직업·여행 상태를 확인할 수 있다. 실내 공간은 이번 범위에 포함하지 않는다.
- 새 건물이 저장된 캐릭터 위치와 겹치는 경우 주변의 통행 가능한 위치로 복구하고 로그를 남긴다.

## 편지와 마을의 지식

`WorldSocietyNetwork.cpp`가 마을 지식과 운반 과정을 관리한다.

1. 45초마다 각 마을이 자기 지역의 인구·재산·치안·상업·학습 환경과 최근 살인/약탈 건수를 기록한다.
2. 마을마다 동시에 한 통의 발송 편지를 허용한다. 시장 당번을 제외한 건강한 상인이 전령을 맡는다.
3. 도로망에서 인접한 마을로 전달한다. 목적지는 순환하며, 출발 시점에 이미 알고 있던 다른 마을의 소식도 함께 담는다.
4. 편지는 전령의 실제 이동과 연결된다. 도착하기 전에는 수신 마을의 지식을 바꾸지 않는다.
5. 도착하면 더 새로운 보고서만 수신 마을의 지식에 반영한다. 다른 마을에서 중계하더라도 최초 작성 시각을 유지한다.
6. 전령은 자기 집으로 돌아간 뒤 일상 활동으로 복귀한다.
7. 전령이 사망하면 운반 편지는 유실된다. 자동 도착 처리는 하지 않으며 이후 발송 주기에 다시 전한다.

편지에는 출발 당시의 보고서가 들어간다. 다른 마을의 최신 상태를 언제나 알고 있는 방식이 아니다.
HTML 모니터는 개발자의 관측 화면이므로 실제 전체 상태와 각 마을이 알고 있는 상태를 모두 보여준다.
개별 소문의 문장 생성, 거짓 소문, 우편함·플레이어 편지 작성은 후속 확장 사항이다.

## 이사 결정과 실행

주민은 자기 마을의 보고서와 **전달받은** 타 마을 보고서를 비교한다.

- 약탈 성향이 낮을수록 안전한 환경을 선호한다.
- 약탈 성향이 높을수록 낮은 치안과 부의 축적 가능성을 선호한다.
- 상인은 상업 환경의 비중이 크다.
- 깨달음을 목표로 하는 주민은 학습 환경의 비중이 크다.
- 체력 성장을 목표로 하는 주민은 안전에 추가 가중치를 둔다.
- 현재 환경보다 점수가 9 이상 높은 경우 후보가 된다.
- 전달받은 소식이 600초보다 오래되었거나, 소식상 인구가 45명 이상이면 해당 마을을 후보에서 제외한다.
- 주민별 판단 대기 시간과 마을당 한 번의 발송 주기에 최대 한 명의 이사 출발 제한을 둔다.
- 도착하면 집·마을만 변경하며 체력·재산·전승·개인 ID는 이어진다.
- 이사 중 사망하면 예약을 해제하고 기존 집에서 부활한다. 재판단에는 대기 시간이 적용된다.

목표 마을의 실시간 인구를 몰래 조회해 매력을 결정하지 않는다. 전달된 인구가 오래되었다면 실제 인구와 차이가 날 수 있다.
빈 필지의 중복 예약 방지는 게임 내부의 일관성 검사이며, 주민에게 최신 원격 경제 상태를 공개하지 않는다.

## 야외 활동과 성능 구조

마을 안의 일반 야생 몬스터 슬롯은 비활성화하고, 기존 사냥터 6곳은 마을 경계 바깥에 배치한다. 전체 마을 사냥터는 42곳이다.
야외 청크의 일반 몬스터와 리젠은 유지한다. 사냥·약탈·거래·수련의 기존 상태 전이도 유지한다.

| 구분 | 처리 |
|---|---|
| 가까운 주민 | 로드된 청크에서 10Hz 판단/이동, 화면 Actor 생성 |
| 먼 주민 | 기록 유지, 누적 시간으로 1Hz 판단/이동, 화면 Actor 없음 |
| 주민 간 밀집 해소 | 로드된 지역에서만 수행 |
| 주민/집/사냥감 Actor | 물리적으로 위치한 청크의 SceneGraph 아래에 배치 |
| 지형 | 플레이어 주변 5×5 청크 로드, 원점 재배치 유지 |
| 건물 모델 | Blender에서 미리 생성한 자산을 한 번 읽고 메시 캐시/배치 렌더러에 전달 |

먼 주민의 전투는 낮은 갱신 빈도로 진행하므로 가까운 전투와 완전히 동일한 프레임 단위 결과를 보장하지 않는다.
실제 NPC 로직을 Blender 프로세스로 보내지는 않는다. Blender는 자산 제작을 위한 별도 백그라운드 프로세스로 사용한다.
현재 구조에는 행성 전역의 대규모 인구를 처리할 작업 스레드·공간 데이터베이스·분산 시뮬레이션이 없다. 필요 시 다음 단계로 분리한다.

## 저장 호환

월드 저장: `ASHEN_WORLD_V6`, 사회 저장: `SOCIETY_V6`, 통신 저장: `TOWN_NETWORK_V1`.
월드 내부에는 레벨 2 상태 `CHAPTER_TWO_V1`도 저장한다.

- 이전 V1~V4 월드/사회 기록을 읽고, 최초 성공 로드 시 이전 월드 파일의 `.pre-world-v5.bak`를 보관한다.
- 기존 전승·성장·아이템·재산은 유지하면서 기존 작은 마을 주민의 위치와 주소를 새 배치로 옮긴다.
- 새 저장에는 집 주소, 이사 예약, 운반자, 편지 내용, 지식 작성 시각, 전령 귀향 상태를 포함한다.
- 중복 집/예약, 존재하지 않는 전령, 편지와 운반자 불일치, 잘못된 ID·범위·숫자를 로드 시 거부한다.
- 실제 사용자 저장 파일은 개발 중 직접 수정하거나 삭제하지 않는다. 변환은 사용자가 새 게임 실행 파일을 실행할 때 발생한다.

## 모니터와 분석 로그

기존 로컬 HTML 모니터와 JSON schema v1을 유지하고 필드를 추가한다.

- NPC: `house_number`, `house_location`, `travel_kind`, `travel_label`, `destination_village`, `mail_id`, `transit_seconds`
- 마을: 실제 인원·방문자·외출자, `houses`, `districts`, `known_news`
- 통신: `communication.letters`, `delivered`, `migrations_completed`
- 원정: `chapter.stage`, `objective`, `complete`
- 편지/이사 출발·완료·유실/중단은 기존 사건 목록에서 확인한다.

주요 로그:

| 이벤트/필드 | 분석 목적 |
|---|---|
| `seven_towns_migrated` | 이전 저장의 새 마을 전환 확인 |
| `letter_dispatched`, `letter_delivered`, `letter_lost` | 전령 ID·편지 ID·출발/도착 마을 추적 |
| `migration_started`, `migration_arrived`, `migration_cancelled` | 주민의 이사와 주소 변경 추적 |
| `migration_decision` | 현재/목적지 점수, 받은 소식의 나이, 예약 필지 추적 |
| `housing_clearance_recovery` | 새 주택과 저장 위치 겹침 복구 |
| `society_summary.near_steps/far_steps` | 가까운/먼 NPC의 갱신 부담 |
| `society_summary.letters/delivered/migrations` | 통신과 인구 이동의 누적 진행 |
| `society_summary.cpu_total_ms/cpu_peak_ms` | 사회 시뮬레이션 CPU 시간 |
| `blender_asset_loaded/fallback` | 파일 자산 로드·폴백 여부 |

기존 draw call, 메시 캐시, 배치 렌더러 성능 로그도 계속 사용한다. 실제 FPS 향상을 측정했다는 의미는 아니다.

## 사용자 실행 확인 항목

사용자 요청에 따라 게임 빌드·게임 실행·화면 확인은 수행하지 않았다. 이번 작업에서는 소스 정합성, 프로젝트 등록, JavaScript 문법, Blender 출력 자산의 구조를 점검한다.

1. 기존 저장으로 시작하고 M에 7개 마을이 표시되는지 확인한다.
2. V/HTML에서 기본 주민 210명과 기존 전승자가 보존되는지 확인한다.
3. 집의 E 안내와 휴식/부활 위치를 확인한다.
4. M 목적지 안내로 이웃 마을로 이동한다. 경계 간 약 20초, 중심 간 약 32초를 구분한다.
5. HTML 편지 목록에서 출발→실제 이동→도착→귀향이 이어지는지 확인한다.
6. 받은 소식이 생긴 뒤 수 분 동안 실행하고 이사 출발/완료와 필지 변경을 확인한다.
7. 전령/이사 도중 저장 후 재실행해 이동과 예약이 유지되는지 확인한다.
8. 전령 사망 시 편지가 유실되고 수신 마을 정보가 즉시 갱신되지 않는지 확인한다.
9. 레벨 1 완료 후 Q 원정 안내에 따라 북쪽 종탑을 진행한다.

## 다음 확장 단계

1. 주민 수 증가에 맞춰 원거리 주민을 마을 단위 경제 모델과 일정 이벤트로 묶는다.
2. 공간 인덱스로 주택·주민·사냥 대상 탐색을 제한한다.
3. 청크별 네비게이션 데이터와 경로 캐시를 추가하고, 로드/언로드 전환 시 경로를 검증한다.
4. Blender 자산의 지붕·벽·장식·지형 모듈을 늘리고 단계별 상세도/재질 공유를 적용한다.
5. 행성 규모가 실제 요구가 되면 지역 좌표계, 전역 주소, 저장 분할, 비동기 청크 로딩을 별도 설계한다.

- Visual Studio 프로젝트와 필터 XML 파싱, 변경한 소스/헤더/메시 파일의 중복 없는 등록을 확인했다.
