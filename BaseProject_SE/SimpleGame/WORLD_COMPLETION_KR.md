## 월드 좌표와 저장

`PlanetWorld`는 지면의 64비트 청크 좌표를 행성 구획 `(planetX, planetY)`와 구획 내부 좌표로 나눈다.
가로 1,565,440청크 × 768단위, 30단위/미터 환산으로 둘레 약 40,075km 크기의 주소 공간이다.
음수 좌표와 구획 경계를 처리하며, 실제 게임 렌더링은 원점 재배치를 사용하는 2.5D 지면을 유지한다.

이는 **구형 지형의 곡률·극지·궤도 비행을 추가한 것이 아니다**. 행성 크기의 구획 식별과 필요한 지역만 생성·저장하는 기반이다.
현재 직접 배치된 마을은 7개이며, 그 바깥에는 기존 절차 지형 생성이 계속된다. 모든 행성에 도시와 무한 NPC를 미리 배치하지 않는다.

- 새 저장소: `%LOCALAPPDATA%\AshenInheritance\World_v1.txt.sqlite3`.
- Windows 기본 SQLite API를 사용한다. 별도 SQLite 설치/서버는 필요 없다.
- `core`에는 플레이어·전승·성장·NPC·편지·마을 지식·현재 지역의 V6 스냅샷을 저장한다.
- `regions`에는 방문한 각 지역의 채집·몬스터·드랍·불씨 상태와 마지막 시뮬레이션 시간을 저장한다.
- 행성 구획 인덱스를 함께 저장하며, 지역 키로 필요한 기록만 읽는다.
- 월드와 지역을 하나의 트랜잭션으로 커밋한다. WAL과 FULL 동기화를 사용한다.
- 저장 후 지역 캐시가 128개를 넘으면 활성 청크·체크포인트·원정 거점 외의 기록을 메모리에서 내린다.
- 내린 지역의 몬스터 리젠 시간은 다시 읽을 때 게임 내 경과 시간을 반영한다. 실제 PC를 꺼둔 시간은 시뮬레이션하지 않는다.
- 읽기 실패·지원하지 않는 DB 버전에서는 잘못된 초기 상태로 덮어쓰지 않는다.
- 기존 프로필 잠금을 유지하므로 같은 저장소에 게임 두 개가 동시에 쓰지 않는다.

첫 V5 텍스트 저장 로드 시 검증을 통과한 후 `.pre-world-v6.bak`을 보관한다.
기존 8청크 간격의 마을 구역을 새 5청크 간격으로 옮긴다. 주민 ID·재산·필지·전승·편지의 마을 번호는 보존한다.
플레이어·체크포인트·전승자의 위치가 이전 마을 구역 안에 있었다면 같은 구역 오프셋으로 옮긴다.
배치 변경으로 지역 기록의 키가 겹치면 진행 기록을 보수적으로 병합한다. 야외에서 이동 중이던 NPC는 같은 집 기준 상대 위치를 유지하고 새 목적지까지 계속 이동한다.
이후 SQLite가 최신 저장소이며 기존 텍스트 파일은 이전용 원본으로 남는다. 백업할 때는 실행 중 복사보다 게임 종료 후 저장 폴더 전체를 복사하는 편이 간단하다.

## 원거리 NPC 작업자

`FarSimulation`은 게임 객체를 다른 스레드에서 직접 수정하지 않는다.

1. 메인 스레드가 주민·사냥터·편지·지식의 논리 상태 사본을 만든다.
2. 작업자는 같은 `WorldSociety::Think`를 사용해 최대 64명의 먼 주민을 계산한다. 순환 선택으로 특정 ID만 계속 계산하지 않도록 한다.
3. OpenGL, 실제 플레이어의 상태, 실제 저장소, HTTP 모니터는 작업자에서 사용하지 않는다.
4. 메인 스레드가 변경된 모든 주민·사냥터·지식·편지를 비교한다. 그 사이 바뀌었거나 화면 안으로 들어온 주민과 충돌하면 해당 묶음을 반영하지 않는다.
5. 반영은 묶음 단위다. 거래 상대 한 명의 돈만 바뀌는 부분 반영을 하지 않는다. 사건 ID와 소문 원본 ID도 메인 스레드에서 다시 연결한다.
6. 거절한 계산의 미처리 시간은 유지한다. 지연이 2.5초를 넘으면 메인 스레드가 보완 계산한다. 작업 스레드를 만들지 못한 경우에도 기존 방식으로 진행한다.

Blender는 NPC AI 작업자가 아니다. 게임 규칙은 C++ 작업 스레드에 두고, Blender 프로세스는 자산 내보내기만 맡는다.
네트워크 발송·사냥감 리젠·가까운 전투·화면 프록시 생성은 메인 스레드가 관리한다.
작업자의 입력 복사와 결과 검증은 메인 스레드 비용이므로 전체 프레임 비용이 사라지지는 않는다. 실제 개선 폭은 사용자가 실행 후 측정해야 한다.

## Blender 별도 프로세스

설정은 `Assets/모델.txt`에 추가했다.

```ini
source_blend = BriarGlen_AssetLibrary.blend
auto_export = true
# 설치 경로가 다르면 지정
# blender_executable = C:\Program Files\Blender Foundation\Blender 5.2\blender.exe
watch_md = @config/LOADER_CONTRACT.md
```

- .blend가 안정적으로 관찰되면 자동 내보내기. F10으로도 요청 가능하다.
- Blender는 창 없이 백그라운드·낮은 우선순위·2개 작업 스레드로 실행한다. 포함된 자동 스크립트 실행은 끈다.
- 게임이 소유한 `Tools/export_asset_snapshot.py`만 실행한다. 모델 제작 쪽의 임의 Python이나 MD를 실행하지 않는다.
- 원본 .blend와 원본 GLB/FBX는 저장하거나 덮어쓰지 않는다.
- `%LOCALAPPDATA%\AshenInheritance\RuntimeAssets\<root해시>\generation_*`에 결과를 만든다.
- manifest에 지정한 메시·리그를 선택하고, GLB 헤더·노드·클립을 확인한 후 `current.json`을 원자적으로 교체한다.
- 최신 두 생성 폴더를 남기며, 해당 캐시 아래의 검증된 생성 폴더만 정리한다.
- 실패·시간 초과 시 기존 정상 모델을 유지한다. 수정하거나 F10을 누르면 다시 시도한다.
- 캐시보다 새로운 수동 GLB가 원본 폴더에 있으면 그 파일을 우선한다.
- 게임 종료 시 게임이 띄운 내보내기 프로세스만 정리한다. 사용자가 열어 둔 Blender는 건드리지 않는다.

기본 자동 검색은 Blender 5.2/4.5의 표준 설치 위치다. 다른 버전은 설정으로 경로를 지정한다.
새 제작물도 현재 manifest 형식과 정식 노드 이름을 유지해야 한다. 리그 이름이 달라지면 NPC 프리셋의 rig 필드도 맞춘다.

## MD와 애니메이션

`Assets/LOADER_CONTRACT.md`의 `ashen-assets` 블록이 실제 로더 규칙이다.
역할별 모델 목록·클립 이름·재생 길이·배율·포즈 FPS·입력 데이터 상한을 실행 중 다시 적용한다.
지원하지 않는 기능을 요구하거나 잘못된 모델 ID를 지정하면 마지막 정상 규칙을 유지하며 오류를 기록한다.
일반 자연어 기획을 임의로 코드로 바꾸는 기능은 포함하지 않는다.

- C를 누른 상태로 이동: 기본 속도의 1.45배, Run.
- J: Jump. 기본 클립 길이 후 착지, 추가 1초 재사용 대기, 초반 0.25초 피격 보호. 장애물을 넘는 지형 이동은 아니다.
- 정지 상태에서 대화 상대/공격 방향 등이 바뀌면 TurnLeft/TurnRight.
- 방향은 부드럽게 보간하며, 렌더 메시 캐시는 16방향으로 양자화한다.
- 클립 전환은 약 0.12초 동안 로컬 TRS를 섞는다. 전환이 끝나면 이전 시간은 캐시 키에서 제거해 캐시가 매 프레임 늘어나지 않게 한다.
- 전환 클립의 root 회전은 시각 방향과 중복 적용하지 않는다. root_bone 이름은 계약에서 지정한다.
- 몬스터는 manifest.animals에서, NPC 부품은 manifest.npc_parts에서 선택한다. 새 변형 추가는 카탈로그 갱신 후 반영된다.

## 검증 상태와 사용자가 실행할 점검

요청에 따라 게임 빌드·실행·화면 검수 및 Blender 내보내기 실행은 수행하지 않았다.
정적 검사: MSVC의 `/Zs`로 실행 파일·오브젝트를 생성하지 않고 프로젝트 C++ 54개 문법 검사, 프로젝트 XML과 스크립트 구문 검사.
실행 중 동작과 성능은 아래 절차로 확인한다.

1. Visual Studio에서 x64 Debug/Release를 빌드한다. 새 소스와 계약·내보내기 도구는 프로젝트에 등록되어 실행 폴더로 복사된다.
2. M 지도의 새 간격과 첫 마을 출발 후 이웃 중심까지 약 20초를 확인한다. 달리기·전투·우회 시간은 제외한다.
3. C 이동, J 점프, 주민 회전, F9 재로드, F10 내보내기를 확인한다.
4. 마을 밖 이동·편지 도착·이사·즉시 부활을 관측소에서 확인한다.
5. 종료 후 다시 시작해 개인 집·재산·전승·지역 채집 기록이 유지되는지 확인한다.
6. 모델 제작 쪽에서 새 GLB/manifest/계약을 저장하고 정상 교체 및 오류 시 마지막 정상 모델 유지를 확인한다.

선택적으로 실행 파일의 `--self-test`를 사용하면 그래픽 창과 모니터 포트 없이 논리 통합 점검을 실행할 수 있다.

```powershell
# 존재하지 않는 새 폴더의 절대 경로만 허용. 평소 게임 저장소는 열지 않음.
.\SimpleGame.exe --self-test C:\Temp\AshenChecks_20261027_A
```
