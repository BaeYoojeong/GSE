## 1. 문제와 원인

NPC가 같은 장소에 모이고 몬스터가 한곳에서 계속 나타나는 문제를 위치 선택과 생성 수명주기에서 수정한다. 좌표의 SceneGraph 부모 변환은 청크 원점을 정상 반영하고 있었다. 소스 검사에서는 정상 호출만으로 Actor가 무한 중복 생성되는 경로를 확인하지 못했다. 중복 방어를 보강하되, 확인된 군집 원인을 함께 고친다.

| 기존 동작 | 군집에 미친 영향 | 변경 |

## 2. NPC 위치와 행동

아래 좌표는 768단위 청크 안의 로컬 좌표다.

| 행동 | 후보 위치 | 규칙 |
|---|---|---|
| 휴식·부활·전승자 시작 | x=120,164,208,252 / y=362,406,450 | 다른 주민의 현재 위치와 목적지를 고려해 덜 붐비는 후보 선택 |
| 거래 | x=324,364,404,444 / y=350,398,446 | 시장 중심 (384,410)의 거래 범위 안에서 분산 |
| 수련 | x=516,560,604,648 / y=362,406,450 | 광장 동쪽의 안전한 도로 공간 사용 |
| 남북 이동 | x=328,356,384,412,440 | 기존 확보 도로 안에서 주민별 통과 위치 선택 |

목적지는 행동이 바뀔 때 정하며 매 틱 임의 좌표로 바꾸지 않는다. 주변 주민의 목적지 예약과 현재 점유에 비용을 더해 같은 자리를 피한다. 이미 한곳에 저장된 주민도 이후 이동과 간격 조정의 대상이다.

간격 조정은 같은 마을의 32단위 셀과 인접 셀을 비교한다. 32단위보다 가까우면 조금씩 떨어뜨리며, 도로·열린 들판 범위와 로딩된 충돌 지형을 확인한다. 월드 밖에서도 주민 기록에 같은 규칙을 적용하고 화면 Actor는 그 결과를 반영한다. 이는 고정 인구 프로토타입의 지역 이동·분리 규칙이며 범용 내비게이션 메시나 수만 명 군중 성능 검증을 의미하지 않는다.

사냥 후보 점수 계산은 예약을 만들지 않는다. 실제 사냥을 선택할 때만 슬롯을 예약하며 다른 예약자가 2명인 대상은 제외한다. 빈 대상 우선 비용, 거리, 기존 대상 유지 선호를 함께 적용한다. 두 사냥꾼은 몬스터 좌우 약 34단위에서 공격하며 접근 좌표를 청크 내부 24~744 범위로 제한한다. 공격에는 기존 45단위 거리 조건이 유지된다.

거래 계획은 현재 시장 밖에 있는 적격 상대도 고려한다. 실제 자산 교환은 판매자와 구매자 모두 시장 범위 안에 있어야 한다. 휴식·수련으로 시장을 떠난 뒤 누구도 거래를 다시 선택하지 못하는 상황을 방지한다.

## 3. 사냥터 생성과 리젠

거점당 슬롯은 4개로 유지한다. 남쪽의 분리된 영역 중심은 `(80,710)`, `(280,560)`, `(488,560)`, `(690,710)`이다. 각 중심에서 x/y 최대 24단위 떨어진 8개 후보를 사용한다. 슬롯의 ID와 보상은 유지하면서 리젠 때 후보를 순환한다.

`PlaceQuarry(game, ground, respawn)`이 최초 생성·로드·전승으로 생긴 거점·리젠의 배치 검사를 공유한다.

1. 플레이어가 살아 있고 같은 청크에 있으면 90단위 이상 떨어진 후보를 찾는다.
2. 살아 있는 주민과 56단위 이상 떨어진 후보를 찾는다.
3. 일반 몬스터 두 슬롯의 생성 예정 위치와 64단위 이상 거리를 확보한다. 아직 일반 몬스터 Actor가 만들어지기 전에도 적용한다.
4. 로딩된 청크에서는 현재 일반 몬스터 위치와도 64단위 이상 거리를 확보하고 지형 충돌을 검사한다.
5. 조건을 만족하는 후보가 없으면 배치를 보류하고 다음 사회 갱신에서 다시 시도한다.

최초·로드 배치가 보류된 대상은 숨기고 자동 조준·플레이어 피해 처리·NPC 사냥에서 제외한다. 위치가 없는 대상이 화면과 전투에서 서로 다른 상태를 갖지 않도록 한다. 기록의 체력과 기존 보상 상태는 배치만으로 초기화하지 않는다.

처치된 슬롯은 최소 **2초의 시뮬레이션 시간**을 기다린다. 이후 안전한 후보를 찾았을 때 체력 60, 공격 대기 1초로 복구한다. 자리가 계속 점유되면 리젠은 더 늦어질 수 있다. 네 슬롯이 모두 죽어도 대기를 무시하고 즉시 한 마리를 살리지 않는다. 이 때문에 사냥 대상이 잠시 없는 시간이 가능하며, NPC는 다른 행동을 재평가한다.

## 4. 일반 몬스터와 Actor 소유권

일반 몬스터는 기존 청크당 2슬롯과 5초 리젠을 유지한다. 생성 지점 기준 플레이어 거리 240단위 이내에서 추적하며, 자신이 생성 지점에서 260단위 이상 벗어나거나 목표 시야를 잃거나 플레이어가 보호된 불씨 영역에 들어가면 귀환한다. 움직이거나 싸우는 동안 주변 주민·사냥터·일반 몬스터와 42단위 간격을 확보하는 힘을 적용한다. 간격 값은 이동 중의 목표치이며 모든 프레임에 강제 보장되는 위치 제약은 아니다.

`Game::Spawn`은 Enemy/Quarry에 대해 같은 종류·청크·슬롯의 살아 있는 SceneGraph 노드가 있으면 새 노드를 만들지 않는다. 일반 몬스터 리젠은 기존 슬롯 Actor를 먼저 확인하여 중복 생성과 불필요한 체력 초기화를 피한다. 기존 드롭 정리와 보상 비트 초기화 순서는 유지한다.

전승 NPC 생성은 중복에 안전한 `SpawnVillage`를 재사용한다. 주민은 ID, 사냥터와 일반 몬스터는 청크·슬롯, 묘비는 원래 LifeId를 기준으로 동일 대상의 추가 생성을 피한다. 청크 언로드는 Actor만 제거하고 주민·사냥터 기록은 유지한다.

## 5. 구조와 저장

| 파일 | 책임 |
|---|---|
| `WorldSociety.cpp` | 사회 틱, 행동 실행, 거래, 피해·보상, 즉시 부활, Actor 상태 반영 |
| `WorldSocietyDecision.cpp` | 행동 점수, 거래 상대 계획, 사냥 자리 예약·선택 |
| `WorldSocietySpatial.cpp` | 활동 위치, 도로 이동, 주민 간격, 사냥터 배치·리젠, 밀도 진단 |
| `WorldSociety.h` | 영구 기록과 실행 중 파생 위치·예약 상태 선언 |
| `DarkAgeWorld.cpp` | 청크 Actor 생성과 슬롯 중복 방어 |
| `DarkAgeCombat.cpp` | 전투 대상 적격성, 일반 몬스터 리젠·드롭 세대 처리 |
| `EnemyActor.cpp` | 일반 몬스터 추적 범위·귀환·근거리 간격 |

저장 형식은 **ASHEN_WORLD_V4 / SOCIETY_V2**로 유지한다. 저장 파일을 삭제하거나 새 세계를 만들 필요가 없다. NPC ID·재산·체력·성장·전승 관계와 사냥터 슬롯·체력·리젠 시간은 기존 기록을 사용한다.

행동 목적지, 예약된 사냥 자리, 사냥터 좌표·후보 번호·배치 대기는 실행 중 파생 상태다. 재실행 시 새 분산 규칙과 현재 점유를 바탕으로 계산하므로 몬스터의 좌표가 저장 직전과 같다는 보장은 없다. 주민 위치는 기존처럼 저장하며 실제 이동 중 분산시킨다.

NPC 즉시 부활은 그대로다. 같은 ID와 남은 재산을 유지하고 3초 보호를 적용하며, 부활 위치만 덜 붐비는 서쪽 휴식 공간으로 바꾼다. NPC 사망으로 총인구가 줄거나 새로운 시작 자산이 생성되지 않는다. 플레이어의 죽음에 따른 전승 NPC 추가는 유지한다.

## 6. 진단 로그

| 이벤트 | 관찰 내용 |
|---|---|
| `population_spacing` | 10초마다 주민 수, 64단위 셀 최대 밀도, 사냥터 슬롯·배치 대기, Actor 수, 일반 몬스터 슬롯 상한, 실제 중복 수 |
| `quarry_spawn_position` | 최초/로드 배치의 청크·슬롯·x/y·후보 번호 |
| `quarry_respawn` | 대기와 점유 검사를 통과한 리젠 위치 |
| `quarry_respawn_deferred` | 모든 후보가 점유되어 배치를 보류한 상태. 동일 대기 중 매 틱 반복하지 않음 |
| `monster_duplicate_prevented` | 같은 슬롯의 추가 생성 요청을 막고 기존 Actor 재사용 |
| `enemy_respawn` | 일반 몬스터의 청크·슬롯·로딩 여부 |
| `enemy_respawn_existing_slot` | 리젠 요청에 이미 존재하는 일반 몬스터 슬롯 확인 |
| `society_transition` / `society_summary` | 행동 선택과 인구·경제·CPU 시간의 기존 기록 |

`population_spacing`은 콘솔과 기존 프로파일 이벤트 파일에 남긴다. `npc_peak_64u_cell`은 밀도 추세이며 값 2 이상이 곧 버그라는 뜻은 아니다. `quarry_alive`는 체력이 양수이고 초기 배치 대기가 끝난 슬롯 수다. `duplicate_actors`는 0이어야 하고 `enemy_actors`는 `enemy_slot_limit` 이하여야 한다. 사냥터 Actor는 죽거나 대기하는 동안에도 숨겨진 슬롯 표현으로 남을 수 있으므로 Actor 수와 화면에 살아 있는 개체 수를 구분한다.

2초 대기 검수는 처치에 대한 society 이벤트와 같은 청크·슬롯의 `quarry_respawn`을 함께 확인한다. 기록 시각과 시뮬레이션 시간은 창 포커스·일시 갱신 중단 상황에 따라 차이가 있을 수 있다. 기존 `quarry_floor_respawn` 이벤트는 이 구현에서 생성하지 않는다. 중복 방지 이벤트 자체는 초과 개체 발생의 증거가 아니며, 실제 개체 중복은 별도 카운터로 확인한다.

## 7. 사용자 실행 확인

아래 항목은 아직 실행 검수를 통과한 결과가 아니다.

- [ ] 기존 세이브로 시작하여 NPC ID·재산·전승자 수가 유지되는지 확인한다.
- [ ] `V`를 열고 휴식·거래·수련 장소와 이동 경로가 분산되는지 관찰한다.
- [ ] 상인이 시장을 떠난 뒤에도 다시 거래에 참여하며 `E → B/N`이 정상 작동하는지 확인한다.
- [ ] 같은 사냥터에 NPC 예약자가 2명을 넘지 않고 몬스터와 같은 점에 포개지지 않는지 확인한다.
- [ ] 네 사냥터를 모두 처치하고 최소 2초 대기와 위치 순환을 확인한다. 즉시 강제 리젠이 없어야 한다.
- [ ] 사냥터 후보 영역을 점유하여 보류 로그를 만든 뒤 비켜나 재배치가 재개되는지 확인한다.
- [ ] 사냥터 근처에서 저장·재실행하여 플레이어 바로 아래에 숨은 공격 대상이 생기지 않는지 확인한다.
- [ ] 일반 몬스터를 마을 쪽으로 유인한 뒤 목표를 벗어나면 원래 구역으로 귀환하는지 확인한다.
- [ ] 일반 몬스터의 5초 리젠, 이전 드롭 정리, 한 번의 처치 보상을 확인한다.
- [ ] 주민을 처치해 동일 ID로 즉시 부활하고 3초 보호·총인구 유지가 작동하는지 확인한다.
- [ ] 세 마을 왕복·청크 언로드·플레이어 전승 후 `duplicate_actors=0`과 슬롯 상한을 확인한다.
- [ ] 실제 밀도·활동 전환·CPU 로그를 보관하여 이후 인구 확대나 경로 개선의 기준으로 사용한다.
