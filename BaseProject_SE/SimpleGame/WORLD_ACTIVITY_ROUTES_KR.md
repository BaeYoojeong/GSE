# 주민 이동·상점 분산·몬스터 밀도 조정

후속 변경: 현재 몬스터 수치·야외 활동·약탈 표시·SOCIETY_V4 규칙은 [WILDERNESS_RAID_BALANCE_KR.md](WILDERNESS_RAID_BALANCE_KR.md)를 따른다. 아래 내용은 이전 단계 기록이다.

작성일: 2026-10-14. 현재 중세 암흑시대 오픈월드 프로토타입의 확장 작업이다.

## 문제와 변경 방향

기존 주민 좌표는 소속 마을 청크의 내부로 제한되었고, 거래 목적지 역시 중앙 광장에 집중되어 있었다. 다른 마을 주민과의 거래·약탈 판정도 소속 마을에 묶여 있었다. 적 감소 조정까지 겹치면서 마을 밖 활동이 적어 보일 수 있는 구조였다.

이번 변경은 소속 마을과 실제 위치를 구분하고, 직업별 목적지를 분산한다. 기존 무한 청크 스트리밍과 월드 크기 정책은 유지한다. 주민 개개인의 현재 활동 범위는 소속 마을 및 주변 8개 청크이며, 모든 주민이 무제한으로 방랑하는 구현은 아니다.

## 적과 사냥터

| 항목 | 변경된 규칙 |
|---|---|
| 일반 몬스터 | 모든 청크에 기본 슬롯 1개 활성화 |
| 추가 일반 몬스터 | 초기 3개 마을 외 청크 중 시드 해시로 정한 약 절반에 두 번째 슬롯 활성화 |
| 일반 몬스터 재생성 | 처치 후 기본 8초, 플레이어·NPC가 가까우면 대기 |
| 주민 사냥터 | 소속 마을마다 3개, 슬롯별 동시 사냥 예약 최대 2명 |
| 사냥터 재생성 | 처치 후 기본 4초, 점유·충돌 검사 통과 후 생성 |
| 주민 전투 | 기존 사냥꾼 기본 피해 30 / 주기 0.8초, 기타 직업 22 / 1.1초 유지 |

일반 몬스터 슬롯 수는 생존 수 보장이 아니다. 처치·재생성 대기·지역 로딩 상태에 따라 실제 보이는 수는 달라진다. 중복 Actor 방지와 점유 검사도 유지한다.

새 지역의 일반 몬스터 기본 위치는 청크 서쪽/동쪽 외곽 `(130,560)`, `(650,560)`에 시드별 ±20 변동을 준다. 기존 레이아웃 버전 1 저장 지역은 이전 배치 좌표를 유지한다.

주민 사냥터 중심은 소속 마을 기준 `(210,560)`, `(690,420)`, `(1220,590)`이다. 세 번째는 동쪽 이웃 청크의 `(452,590)`에 해당한다. 중심 주위의 8개 후보 위치로 재생성 위치를 바꾸며, 기존 일반 몬스터·다른 사냥감·주민·플레이어와의 간격을 확인한다. 사냥꾼의 사격 위치도 대상 좌우로 분산한다.

## 주민 이동과 직업 활동

- `CitizenRecord.village`는 영구적인 소속 마을이다. `position`은 해당 마을을 원점으로 하는 좌표다.
- 좌표 허용 범위를 각 축 `[-744,1512]`로 넓혔다. 내부 청크 경계에서 이동을 막지 않고, 활동 범위 바깥에서만 제한한다.
- `Locate()`는 실제 청크와 청크 내부 좌표로 정규화한다. 음수 방향 이동은 내림 연산으로 처리한다. `InFrame()`은 서로 다른 소속의 좌표를 같은 기준으로 변환한다.
- 사냥은 분산된 사냥터와 주변 일반 몬스터를 대상으로 한다. 약탈은 실제 거리 400 안의 대상을 소속과 관계없이 탐색한다.
- 상인은 마을 상점 당번과 다른 마을을 오가는 활동을 나눈다. 마을별 한 명의 당번을 60초마다 순환하며, 다른 상인은 인접한 알려진 마을의 상점을 목적지로 삼을 수 있다.
- 수련은 여러 명소를 순환한다. 인접 마을이 없는 경우에도 이웃 지역의 길과 들판을 방문할 수 있다. 휴식은 소속 마을의 여러 회복 지점으로 나눈다.
- 도착 후 기본 6~10초 체류하면 다음 목적지를 선택한다. 회복 중에는 체력이 충분히 회복된 뒤 이동한다. 기존 체력·재산·재고·성향에 따른 가중치 전이는 유지한다.

이동은 기본 82단위/초, 약탈 시 96단위/초다. 로딩된 지역에서는 충돌 검사를 통과하는 직선 경로를 이용하고, 막히면 도로·들판의 제한된 우회 지점을 확인한다. 지역 간에는 연결된 도로와 남쪽 들판을 이용하며, 정체 시 옆 방향의 충돌 검사로 탈출을 시도한다. 전체 격자 A*는 도입하지 않았다. 로딩되지 않은 지역은 예약된 도로를 중심으로 이동하며 상세 장애물 Actor 검사를 생략한다.

주민 간 간격 검사는 실제 청크와 공간 셀을 기준으로 한다. 소속이 다른 방문객 및 청크 경계 양쪽의 주민도 분리한다. 고밀도 환경이나 복잡한 구형 장애물 배치에서의 경로 품질은 실행 확인이 필요하다.

## 상점 배치와 거래

마을마다 상점을 두 곳에 배치한다. 주민이 서는 거래 기준점은 서쪽 주거지 `(168,404)`, 남동쪽 길가 `(588,660)`이며 상점 모델은 각 기준점보다 38단위 위에 둔다.

당번 상인과 고객의 대기 위치를 나누고, 고객은 거래 가능한 상인의 실제 위치 또는 목적지에 가까운 상점을 선택한다. NPC 간 거래는 같은 실제 청크의 같은 상점 구역에서만 이뤄진다. 각 참가자는 거래 기준점 80단위 안에 있어야 하며 서로의 거리도 130 이내여야 한다. 상점 외관만으로 원격 거래를 허용하지 않는다.

상점 두 곳이 항상 동시에 영업하는 것은 아니다. 상인의 이동·부상·적대·당번 교대에 따라 이용 가능 여부가 바뀐다. 플레이어의 구매·판매와 상인 표시도 동일한 상점 판정 함수를 사용한다.

## Actor와 SceneGraph

영속 주민 기록을 다른 마을로 이동시키는 대신, 화면에 보이는 Actor의 부모를 실제 위치 청크로 바꾼다.

| 데이터 | 의미 |
|---|---|
| 주민 기록의 `village` | 소속 마을, 저장·경제·부활 기준 |
| 주민/사냥감 Actor의 `chunk` | 영속 기록을 찾는 소유 키 |
| Actor의 부모 청크 | 실제 현재 지역, 스트리밍과 화면 배치 기준 |
| Actor의 `position` | 부모 청크 내부의 정규화된 좌표 |

`WorldSocietyActors.cpp`가 동기화·재부모화·누락된 표시 Actor 생성·언로드된 표시 Actor 정리를 담당한다. 영속 주민 기록은 언로드로 지워지지 않는다. 소속 마을이 로딩되지 않아도 현재 지역이 로딩되어 있으면 방문객을 표시한다. 주민 ID와 사냥터 소유 키/슬롯으로 중복 생성을 막는다.

이동 애니메이션은 시뮬레이션의 실제 위치 변화량으로 갱신한다. 공격 이펙트 목표점도 화면 Actor의 실제 부모 좌표계로 변환한다. 사망 후 즉시 고향 부활 시 부모와 위치를 함께 동기화한다.

## 저장 호환성

- 새 저장은 `SOCIETY_V3`를 사용한다. 상위 월드 저장 형식은 유지한다.
- 기존 `SOCIETY_V1`, `SOCIETY_V2`를 읽는다. 기존 주민 ID·소속·재산·사망 횟수는 유지한다.
- V2의 2개 또는 4개 사냥터 구성을 받아들인다. 부족한 세 번째 슬롯을 채우고, 현재 범위를 벗어난 네 번째 슬롯만 제거한다.
- 이전 일반 몬스터 최대 12초, V2 사냥터 최대 6초의 재생성 대기를 읽고 현재 최대 8초/4초로 제한한다.
- 여행 중인 좌표를 저장한다. 목적지·당번·체류 시간·이동 애니메이션 정보는 로드 후 다시 계산한다.

구버전 실행 파일은 새 V3 저장을 읽지 못할 수 있다. 이 작업에서 기존 세이브 파일은 직접 수정하거나 삭제하지 않는다.

## 모니터와 분석 로그

기존 JSON의 `village_id`와 `position` 의미를 유지하면서 다음 정보를 추가한다.

- `location.chunk`, `location.local`: 정규화된 실제 위치.
- `away_from_home`: 현재 청크가 소속 마을 밖인지 여부.
- `destination`, `destination_kind`: 이동 목적지와 활동/사냥감/추적 대상 구분.
- `journey`, `goal_dwell_seconds`: 목적지 갱신 번호와 남은 체류 시간.
- 마을 `population.present`, `away`, `visitors`: 마을 내 소속 주민, 외출 주민, 다른 마을 방문객.

야외에 주민이 방문했다는 이유로 마을을 추가하지 않는다. 모니터의 알려진 청크 집계에는 실제 주민·사냥터 위치도 포함한다. 살인 목격자는 실제 사건 위치에서 거리로 판정하며, 소속이 다른 주민도 목격할 수 있다.

| 로그 | 확인할 내용 |
|---|---|
| `society_destination` | 주민 ID, 소속, 출발·목표 좌표, 의도, 여행 번호 |
| `society_actor_crossing` | 표시 Actor가 이동한 실제 청크 |
| `society_transition` | 행동 전환 전후, 체력·재산·물자, 활동 점수 |
| 기존 주민 주기 보고 | 외출 수 `away_from_home`, 소속 마을에서의 최대 이동 거리 `farthest_from_home` |
| `quarry_spawn_position`, `quarry_respawn` | 사냥감 소유 키/슬롯, 실제 위치 청크, 배치 변형 |
| `quarry_respawn_deferred` 및 기존 중복 방지 로그 | 점유로 인한 재생성 대기와 중복 생성 시도 |

이 문서는 행동·배치 변경 보고서다. FPS·draw call·실행 시간 개선을 측정했다는 의미는 아니다. 기존 렌더 배칭과 캐시 구조는 계속 사용한다.

## 검증 범위와 사용자 실행 확인

빌드·게임 실행·브라우저 화면 확인은 사용자 요청에 따라 수행하지 않는다. 소스 형식, JS 구문, 프로젝트 XML 및 신규 소스 등록, 좌표계·저장 호환 흐름을 정적으로 확인한다. 실제 렌더링과 밸런스 결과는 아래 항목으로 확인할 수 있다.

- [ ] 주민이 이웃 지역 사냥터·다른 마을 상점으로 이동하고, 현재 위치가 소속과 달라지는지 확인.
- [ ] 같은 주민을 따라 청크 경계를 왕복해도 표시가 중복되거나 사라지지 않는지 확인.
- [ ] 음수 방향 경계를 넘은 상태로 저장·로드한 뒤 주민 위치가 보존되는지 확인.
- [ ] 상점 두 곳의 분산 배치, 당번 교대, 실제 근거리 거래를 확인.
- [ ] 일반 몬스터와 사냥감의 분산, 처치 후 8초/4초 기본 대기 및 점유 시 연기를 확인.
- [ ] 방문객의 공격 방향과 이동 애니메이션, 사망 직후 고향 부활을 확인.
- [ ] 이전 저장을 불러와 주민 수·재산이 유지되고 사냥터가 3개로 구성되는지 확인.
- [ ] 모니터의 외출/방문 수, 현재 위치, 목적지와 실제 주민 행동을 비교.
