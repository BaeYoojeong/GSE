# 외부 Blender 자산 로더

작성 기준: 2026-10-27. 기존 OpenGL 2.5D 게임의 자산 로딩·애니메이션·갱신 구조를 확장한다.

## 확인한 제작 자료

관련 Codex 작업 「모델링·리깅 에셋 제작」에서 아래 제작 폴더를 찾았다.

```text
C:\Users\yujun\Documents\Codex\2026-10-26\referenced-chatgpt-conversation-this-is-an\outputs
```

확인한 파일: `README_KO.md`, `asset_manifest.json`, `rig_schema.json`, `검증_요약.md`, GLB 실제 데이터.
기존 `모델.txt`는 찾지 못했다. 사용자가 “없으면 만들어”라고 지정하여 게임 프로젝트에 `Assets/모델.txt`를 새로 만들고 위 제작 폴더를 기본 경로로 연결했다.
이후 다른 제작 폴더를 사용하면 새로 만든 모델.txt의 root를 갱신한다.

현재 명세는 `village_assets_1.0`, 미터 단위, 30FPS 키프레임이다. 기본 카탈로그에는 NPC 프리셋 4개, 동물 7종, 환경 13종, 조합용 NPC 라이브러리 1개가 있어 총 25개 자산을 등록한다.
추가 리타게팅 데모를 포함해 현재 폴더의 GLB 26개를 읽기 검사했다. 제작 원본과 FBX는 수정하지 않는다.

## 설정과 경로

설정 파일은 UTF-8이며 다음 키를 지원한다.

```ini
root = C:\...\outputs
manifest = asset_manifest.json
watch_md = README_KO.md
watch_md = 검증_요약.md
watch_md = @config/LOADER_CONTRACT.md
auto_export = true
source_blend = BriarGlen_AssetLibrary.blend
rig_schema = rig_schema.json
enabled = true
poll_seconds = 1
pose_fps = 12
units_per_meter = 30
```

- `root`: 자산 폴더. 절대 경로 또는 모델.txt 위치 기준 상대 경로.
- `manifest`: root 기준 상대 경로. 카탈로그 자산 파일 경로는 root 밖으로 벗어날 수 없다.
- `watch_md`, `rig_schema`: 변경 여부를 기록할 문서. 여러 줄을 사용할 수 있으며, root 기준 상대 경로나 명시적인 절대 경로를 지원한다.
- `enabled`: 외부 모델 사용 여부. `false`이면 기존 모델을 사용한다.
- `poll_seconds`: 0.5~60초, 기본 1초.
- `pose_fps`: 렌더 캐시에 사용할 포즈 간격, 1~30FPS, 기본 12FPS. 원본 키프레임을 삭제하거나 다시 내보내지 않는다.
- `units_per_meter`: 월드 단위 환산, 기본 30.
- 주석은 `#` 또는 `;`로 시작한다. 경로만 한 줄 적는 최소 형식도 가능하다.

설정 파일 선택 순서:

1. 환경변수 `ASHEN_MODEL_CONFIG`가 지정한 모델.txt.
2. 개발 실행 폴더에서 최대 네 단계 상위까지 찾은 `SimpleGame/Assets/모델.txt`.
3. 실행 파일 폴더의 `Assets/모델.txt`.

실제로 선택한 경로는 `asset_config_path` 로그에 남는다. 개발 빌드에서는 소스 폴더의 설정을 직접 감시하므로 설정 수정 때마다 재빌드할 필요가 없다.
배포 폴더에는 모델.txt가 복사된다. 다른 PC에서는 root를 해당 PC의 자산 폴더나 함께 배포한 상대 경로로 수정한다.

## 로더 구조

```text
Assets/모델.txt
  → AssetCatalog: 경로·카탈로그·부품 인덱스·변경 감지
  → GltfModel: GLB 메시·본 계층·가중치·역바인드·클립 읽기
  → GltfPose: TRS 샘플링·보간·스키닝·현재 카메라로 투영
  → MeshCache: 같은 모델/부품/방향/포즈의 메시 공유
  → RenderBatch: 기존 배치 렌더링
  → 기존 HDR/Bloom/비넷/가장자리 블러
```

Blender 설치나 실행 중 Blender 프로세스는 런타임 로딩에 필요하지 않다. `.blend`를 편집한 뒤 GLB로 내보내면 된다.
GLB의 자급식 버퍼를 직접 읽으며 외부 버퍼 URI나 이미지 파일을 따라 읽지 않는다. 현재 작업의 단색 재질 자산에 맞춘 범위다.

## 지원 범위

- GLB 2.0의 삼각형 메시와 인덱스, 노드의 TRS 또는 고정 행렬.
- 단색 PBR 기본 색상, 발광 색/세기, 양면 여부. 기존 렌더러에 맞춘 단순 명암과 발광으로 변환한다.
- 부모-자식 본 계층, `JOINTS_0`, `WEIGHTS_0`, 역바인드 행렬, 정점당 최대 4개 가중치.
- 정점 가중치를 정규화하고, `jointWorld × inverseBind` 결과를 사용한다. 메시의 월드 변환을 다시 곱하지 않는다.
- 위치·회전·스케일 키프레임과 LINEAR/STEP/CUBICSPLINE 보간.
- 쿼터니언 최단 경로 SLERP, 비선형 보간 후 회전 정규화.
- 루프 클립과 끝 포즈를 유지하는 비루프 클립.
- `GltfModel::Pose`의 이전 클립·시간·blend 값으로 두 포즈의 로컬 TRS를 블렌딩하는 API.
- glTF의 Y-up을 게임의 지면 X/Y·높이 Z로 바꾸고 기존 45도 카메라로 투영한다.

텍스처, 투명/마스크 재질, 모프 타깃, Draco, 필수 확장, 여러 외부 버퍼, sparse accessor는 이번 버전의 지원 범위에 포함하지 않는다.
해당 기능을 가진 새 파일은 조용히 잘못 그리지 않고 오류 코드와 함께 거부한다. 기존 정상 모델이 있으면 그 모델을 유지한다.
완전한 PBR/3D 카메라·동적 조명·GPU 스키닝은 별도 렌더러 확장 사항이다.

## 조합형 NPC

manifest의 `npc_parts`에 정의된 슬롯·인덱스·메시명을 읽는다. 라이브러리 전체를 한꺼번에 그리지 않고 슬롯마다 선택한 하나의 부품만 포함한다.

실제 GLB를 확인한 결과, Blender 메시 데이터 이름은 `Cube.002`·`Icosphere` 등의 이름을 가진다.
명세의 안정적인 `NPC_Face_00` 등은 **오브젝트 노드 이름**에 보관되므로 노드 이름을 부품 식별자로 사용한다.
새로 내보낸 라이브러리의 필수 부품 노드가 사라졌으면 교체를 거부한다.

`AssetCatalog::Request.parts`는 슬롯별 인덱스 맵이다. 기본 게임 연결에서는 주민의 영속 ID와 직업을 이용해 Face/Hair/Torso/Outfit을 결정한다.
따라서 같은 주민은 청크가 다시 로드되거나 다른 마을로 이사해도 같은 인덱스 조합을 얻는다.
이는 기존 저장 포맷에 편집 가능한 외형을 추가한 것이 아니다. 이후 외형 편집 기능을 만들면 선택한 인덱스를 주민 저장 레코드에 넣어야 한다.
모든 슬롯은 현재 카탈로그에 등록된 인덱스에서 선택하며, Outfit은 직업에 따른 변형을 고른다. 명시한 인덱스가 없으면 오류를 기록한다.

기존 인덱스와 이름은 유지하고 새 변형은 뒤에 추가하는 제작 규칙을 따른다.

## 애니메이션 연결

게임의 현재 이동 상태는 Idle/Walk로 연결하고, 약탈 이동 중인 주민은 Run을 사용한다.
플레이어·주민·동물 모두 골격 클립을 샘플링한다. 움직임은 기존 게임 이동 로직이 담당하며 애니메이션의 root 변위를 게임 위치에 중복 적용하지 않는다.

J 입력은 Jump에 연결하며, 정지 중 방향이 바뀌면 TurnLeft/TurnRight를 재생한다. C 이동은 Run을 사용한다.
비루프 클립은 `Request.loop=false`로 재생한다. 새 클립은 명시적으로 이름을 지정하며, 없는 클립은 Idle로 폴백하고 로그를 남긴다.
기본 렌더 어댑터는 `GltfModel::Pose`로 약 0.12초 동안 이전/새 클립을 블렌딩한다. 게임 위치와 중복되는 turn root 회전을 제거한다.

종탑·보스·사망한 플레이어·기타 UI는 기존 표현을 사용한다. 외부 모델이 없거나 지원하지 않으면 기존 모델로 폴백한다.
건물과 자연지물에는 기존 충돌 크기에 맞춘 최대 지면 폭을 적용한다. 자산 추가가 마을 배치/충돌체를 자동으로 변경하지는 않는다.
동물 자산의 공격성 분류를 새 AI로 도입한 것은 아니다. 현재 몬스터 슬롯의 동작은 기존 게임 규칙을 따른다.

새 자산을 카탈로그에 등록하면 ID로 로드할 수 있다. 새로운 오브젝트 종류를 월드에 배치하는 것은 Actor/생성 규칙에서 그 ID를 선택하는 별도 단계다.

## 갱신과 실패 처리

- 모델.txt와 manifest의 수정 시각/크기가 바뀌면 카탈로그를 다시 읽는다. 올바르게 읽힌 후보만 한 번에 교체한다.
- 카탈로그 읽기 실패 후에는 5초 간격으로 재시도한다.
- 실제 사용했던 GLB는 기본 1초마다 수정 시각/크기를 검사한다. 두 번 연속 안정적으로 관찰한 변경만 읽는다.
- 한 검사 주기에 최대 두 개의 GLB를 교체해 한꺼번에 갱신되는 부담을 제한한다.
- 읽기 전후 파일 정보가 바뀌면 저장 중으로 보고 새 모델을 채택하지 않는다.
- 새 파일이 잘못되거나 삭제돼도 마지막 정상 모델은 유지한다. 실패한 파일은 다시 변경되거나 F9를 누를 때 재시도한다.
- 아직 사용하지 않은 새 자산은 처음 요청할 때 로드한다.
- **F9**는 설정/카탈로그를 다시 읽고 사용 중 자산을 다음 요청에서 강제로 읽는다. 실패 시 기존 정상 모델을 유지한다.
- MD와 rig_schema 변경 시 `asset_spec_changed`를 남기고 카탈로그를 다시 검증한다. MD의 ashen-assets JSON 규칙은 실행 중 재적용한다. 자연어 문장이나 새 파일 형식을 자동 구현/실행하지 않는다.

제작 도구에서 같은 수정 시각/크기를 보존해 덮어썼다면 F9로 강제 확인한다.
제작 쪽에서는 임시 GLB로 내보낸 뒤 완성된 파일을 교체하고, 새 파일을 먼저 배치한 다음 manifest를 갱신하는 순서를 권장한다.

## 캐시와 성능

- GLB 원본은 자산별 한 번 로드하고 공유한다. 로드된 CPU 모델은 128MiB 기준 LRU 예산을 둔다.
- 포즈/방향/부품 인덱스가 같은 모델은 GPU 캐시를 공유한다. 모든 NPC가 매 프레임 별도 메시를 만들지 않는다.
- 스키닝과 투영은 해당 포즈의 GPU 캐시가 없을 때 CPU에서 계산한다.
- 정적인 환경 메시만 기존 디스크 캐시를 사용한다. 움직이는 포즈는 디스크에 계속 쓰거나 디스크에서 검색하지 않는다.
- 캐시 키에는 원본 GLB 내용 해시, 부품 조합, 클립, 포즈, 방향, 크기와 투영 설정을 포함한다.
- GPU 캐시는 최대 1,024개/64MiB 한도로 넓혔다. 실제 하드웨어의 텍스처 버퍼 한도도 적용한다.
- 핫 리로드한 데이터는 기존 렌더 큐가 사용하는 메시를 덮어쓰지 않고 다른 내용 키를 사용한다. 이전 데이터는 LRU로 정리된다.

여러 외형·애니메이션·방향이 동시에 많으면 포즈 캐시가 교체될 수 있다. 실제 성능은 게임 실행 후 측정해야 한다.
장기적으로는 스키닝 전용 GPU 버퍼와 Actor별 골격 인스턴스를 도입해 CPU 포즈 메시의 양을 줄일 수 있다.

## 로그

`asset_config_path`, `asset_catalog_loaded`, `gltf_asset_loaded`, `asset_reload_rejected`, `asset_clip_fallback`,
`asset_spec_changed`, `gltf_model_evicted`, `gltf_projection_fallback`을 기존 성능 이벤트 파일에 기록한다.

## 검증 기록과 사용자 확인

### 2026-10-27 모델 가독성 조정

- World.vs는 지형에만 정점 격자 스냅을 적용한다. 캐릭터와 건물은 카메라 변환을 유지하면서 원본 투영 정점을 보존해 얼굴과 작은 삼각형이 뭉개지는 현상을 줄인다.
- 외부 GLB의 면별 조명은 방향광과 하늘 보조광으로 계산해 로우폴리 면의 명암 차이를 강화한다. Blender의 조명과 그림자를 그대로 재현하는 기능은 아니다.
- ENV_Cottage는 문과 창문이 있는 glTF +Z 면이 카메라에 보이도록 180도 회전한다.
- 투영 캐시 버전을 projection_v2로 올려 기존 환경 메시 캐시를 재사용하지 않는다.
- 수정한 세 C++ 파일의 MSVC /Zs 구문 검사를 통과했다. 게임 빌드와 실행은 수행하지 않았다.
- World.vs는 Debug/Release 실행 폴더에도 복사했다. 셰이더 변경은 게임 재시작으로 반영되며, 명암과 집 방향 변경은 C++ 재빌드 후 반영된다. F9는 셰이더나 실행 파일을 갱신하지 않는다.

`Tools/inspect_asset_pack.py`는 Blender나 게임을 실행하지 않고 카탈로그와 실제 GLB의 형식·범위·노드·가중치·클립·부품 이름을 읽기 검사한다.

```powershell
python Tools\inspect_asset_pack.py --root 'C:\...\outputs' --report 'asset_audit.json'
```

이번 검사 결과: 카탈로그 25개, GLB 26개, 호환성 검사 실패 0개.
검사 시점의 파일별 해시·노드/클립 수는 `ASSET_LOADER_INPUT_AUDIT.json`에 보관한다. 반영 전에 GLB와 제작 문서의 해시를 다시 확인했고 변경은 없었다.
프로젝트/필터 XML의 파일 등록, 외부 라이브러리의 실제 API 선언, 검사 도구 문법, 정적 메시/애니메이션 포즈의 캐시 분리를 소스 기준으로 확인했다.
이는 새 C++ 로더를 실행한 결과가 아니다. 기존 사용자 선호에 따라 C++ 게임 빌드·실행·렌더 확인은 수행하지 않는다.

사용자 실행 시 확인할 사항:

1. 첫 로드의 `asset_config_path`와 `asset_catalog_loaded`가 원하는 폴더를 가리키는지 확인한다.
2. 플레이어/주민/동물의 Idle/Walk, NPC 외형 구분과 집·자연지물의 크기를 확인한다.
3. Blender에서 GLB 한 개를 재수출하고 2~3초 뒤 변경이 반영되는지 확인한다.
4. 잘못된 파일로 교체했을 때 기존 모델이 유지되고 오류 로그가 남는지 확인한다.
5. 파일을 정상화하거나 F9를 눌러 복구되는지 확인한다.
6. 새 클립/새 부품은 manifest와 실제 노드 이름을 함께 갱신한 뒤 API에서 선택한다.
