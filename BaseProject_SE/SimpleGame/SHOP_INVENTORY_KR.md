# 상점 군집·무기·물약·인벤토리

## 조작

| 키 | 기능 |
|---|---|
| E | 시장의 상인 NPC와 상호작용해 상점 열기 |
| I | 인벤토리 열기·닫기 / 상점에서 인벤토리로 전환 |
| ↑↓ 또는 1~5 | 아이템 선택 |
| Enter / E | 상점에서는 구매, 인벤토리에서는 무기 장착·물약 사용 |
| H | 회복 물약 빠른 사용 |
| N | 상점에서 물자 1개 판매 (+2 동전) |
| Esc | 상점·인벤토리 닫기 |

J 점프 입력과 안내를 제거했다. 방향키 이동, C 달리기, Space 자동 조준 공격은 유지한다. 창을 열면 이동·공격 입력을 비우고 메뉴가 방향키·Space를 소유한다. 세계와 적의 시간은 계속 흐르며, 사망하거나 상점에서 멀어지면 창을 닫는다.

## 무기와 물약

| 아이템 | 가격 | 기본 공격력 / 효과 |
|---|---:|---|
| 여행자의 지팡이 | 기본 지급 | 16 |
| 철제 지팡이 | 18 동전 | 18 |
| 잿불 지팡이 | 60 동전 | 19.5 |
| 회복 물약 | 6 동전 | 최대 체력 35% 회복, 재사용 2초 |
| 물자 | 3 동전 | 기존 채집·불씨·봉헌·나눔 자원 |

실제 발사체 피해는 `장착 무기 기본 공격력 + (레벨-1)*0.25 + 강화*0.45`다. 최대 성장에서도 가장 강한 무기가 35.75 피해이므로, 온전한 72HP 몬스터는 최소 3발이 필요하다. 발사 간격은 앞서 조정한 성장식과 하한을 유지한다. 구매한 무기는 즉시 장착하며 이미 가진 무기를 중복 구매하면 동전을 차감하지 않는다.

물약은 구매 또는 회복 아이템 드랍으로 가방에 들어간다. 자동으로 마시지 않으며, 체력이 가득 찼거나 재사용 대기 중이면 수량을 소모하지 않는다. 무기는 종류별 1개, 물약은 99개까지 보관한다. 물자는 기존 Game.supplies가 유일한 원본이고 가방에서도 같은 수량을 보여 준다. 물약이 가득 찼으면 해당 드랍을 즉시 파괴하지 않는다.

상점은 시장에 있는 상인 NPC와 E로 시작한 거래 세션에서 이용한다. 해당 상인에게 가까이 있고 살아 있는 비적대 상태여야 하며, 같은 NPC에게 동전을 지급한다. 무기·물약은 프로토타입의 상시 판매 품목, 물자는 상인의 실제 재고를 사용한다. 거래 중 이동·적대 전환 등으로 조건이 깨지면 창을 닫는다. B 키나 노점 오브젝트로 상점을 여는 방식은 제거했다. 자세한 지도·포탈·상호작용 규칙은 [새 명세](MAP_PORTALS_KR.md)를 따른다.

## 주민이 상점에 머무르던 원인과 변경

기존에는 경제적으로 거래 가능하다는 이유로 Trade를 반복 선택했다. 구매·판매가 끝나도 같은 중심에 머물렀고, 38단위 반경에 16개의 목적지를 겹치게 두었다. 이전 Trade 이동을 강제로 유지하는 예외도 있어 행동 변경이 취소될 수 있었다.

- 노점별 신규 방문객은 점원을 제외하고 예약·현장 인원을 고려해 3명까지 받아들인다. 가득 찬 시장 대신 다른 활동을 선택한다.
- 목적지는 반경 58, 8개 후보로 넓히고 다른 주민의 위치·예약과 겹치는 후보를 피한다.
- 거래가 끝난 손님은 즉시 방문을 마치고 35~59초 뒤 재방문할 수 있다. 거래가 성사되지 않아도 현장 8~11초 또는 이동 45초가 지나면 다른 활동으로 전환한다.
- 점원 1명은 대기·판매를 계속하며, 다른 주민은 사냥·휴식·수련·약탈 등 성향에 따른 행동으로 돌아간다. 이미 모인 주민은 순간이동시키지 않고 실제로 걸어 나간다. 통행 중이거나 이전 버전에서 모여 있던 주민까지 물리적 인원을 강제로 3명으로 삭제하는 규칙은 아니다.
- 원거리 시뮬레이션 병합의 fingerprint에도 시장 타이머를 포함한다. 모니터 NPC JSON에는 market_cooldown_seconds, market_visit_seconds, market_trip_seconds, market_keeper가 추가되고, 프로파일 이벤트 market_visit_end에 방문 종료 사유가 남는다.

## 구조와 저장

현재 코어는 V8이며 포탈 구역과 추가 백업을 포함한다. 아래 V7 인벤토리 도입 설명과 함께 [V8 명세](MAP_PORTALS_KR.md)를 확인한다.

ItemCatalog는 품목 정의, Inventory는 소지·장착·직렬화, PlayerInventory는 게임 규칙과 상점 거리 검사, InventoryInterface는 메뉴 입력·표시를 담당한다. 노점은 MarketStallActor, 포탈은 WaypointActor로 기존 SceneGraph를 통해 제어한다. 거래 상호작용은 CitizenActor가 담당한다. WorldSocietyMarket은 방문 제한과 자산 거래를 담당한다.

월드 코어는 ASHEN_WORLD_V7로 저장하고, INVENTORY_V1 구역에 소지 수량·장착 무기를 기록한다. V1~V6는 기존 레벨·강화·주민·지역을 유지하고 기본 지팡이로 전환한다. 기존 SQLite 저장을 처음 V7로 전환하기 전에는 SQLite backup API로 core와 누적 지역을 함께 `World_v1.txt.pre-inventory-v7.sqlite3`에 한 번 보관한다. 백업 실패나 손상된 인벤토리는 기존 기록을 덮어쓰지 않고 저장 오류로 처리한다. 사망 후 다음 삶에서도 가방과 장비는 유지한다.

## 확인 범위

사용자의 빌드·실행 선호에 따라 게임 빌드와 렌더링·플레이 확인은 수행하지 않았다. 소스의 입력 참조·프로젝트 등록·저장 버전 분기·형식 및 수치 범위를 정적으로 점검했다. --self-test에는 거래의 동전 보존, 중복 구매, 인벤토리 한도와 잘못된 데이터, 물약 조건, 시장 예약·쿨타임, 기존 V6 저장 백업·전환, 장착·수량 재시작 복원 검사를 추가했다. --window-smoke에는 가방 입력 차단과 점프 키 무시 검사를 반영했다. 이 검사들은 새 사용자 빌드 후 실행해야 하며 이번 작업에서 통과했다고 간주하지 않는다.

예전 GLFW/STUTTER 검증 JSON은 당시 버전의 기록이다. 이번 변경은 UI·전투·시뮬레이션을 바꾸므로 새 버전 성능이나 화면을 나타내는 수치가 아니다.
