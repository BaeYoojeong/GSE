# 화면 선명도와 플레이어 공격 조정 (2026-11-10)

아래 전투 수치는 여행자의 지팡이를 기준으로 한 조정 기록이다. 이후 추가한 무기별 기본 공격력과 인벤토리·상점은 [상점·인벤토리 명세](SHOP_INVENTORY_KR.md)를 따른다.

## 확인한 원인

후처리는 65% 가장자리 블러를 반경 0.65부터 넓게 섞고 있었다. Bloom 강도 0.80과 넓은 피라미드 레벨도 광원 주변을 밝게 덮었다. 기본 장면은 이미 texelFetch로 최근접 픽셀을 표시하므로 선명도 문제를 해상도 확대로 해결하지 않는다.

현재 프로필을 읽기 전용으로 확인한 결과 Lv.30 / 무기 +20이었다. 이전 피해식은 `18 + (레벨-1)*3 + 강화*4`로, 이 상태에서 185 피해였다. 일반 몬스터 72HP / 사냥 몬스터 90HP보다 높다. 발사체는 적중 후 제거하고 즉시 반환하므로, 확인한 경로에서는 중복 적중이 아닌 성장 수치가 한 방 처치의 원인이다.

## 화면 변경

- 가장자리 블러는 기본 OFF. F4로 켜면 바깥 모서리 위주로 약하게 적용한다(강도 0.20, 시작 0.98, 종료 1.42, 반경 0.75).
- Bloom 강도 0.32, 추출 기준 0.90, knee 0.20, 반경 0.85. HDR과 자체 발광은 유지한다.
- Bloom 피라미드 가중치 0.68 / 0.23 / 0.07 / 0.02. 넓은 레벨의 기여를 줄여 광원 근처의 빛 번짐을 중심으로 표현한다.
- 노출 1.00, 비넷 강도 0.22 / 시작 0.70. 장면의 픽셀 샘플링과 내부 해상도는 유지한다. 기본 블러 패스 두 번이 생략된다.
- F7은 이 선명한 기본값으로 복원한다. F1은 개별 Bloom·비넷·블러 설정을 유지하면서 후처리 전체만 토글한다.

## 공격 변경

피해는 `16 + (레벨-1)*0.25 + 강화*0.45`, 발사 간격은 `max(0.36, 0.72 / (1 + (레벨-1)*0.02 + 강화*0.02))`로 조정한다. 레벨·강화의 이점은 유지하고 피해량과 연사 속도가 동시에 과도하게 커지는 것을 줄인다.

| 성장 | 발당 피해 | 간격 | 72HP 적 | 90HP 적 |
|---|---:|---:|---:|---:|
| Lv.1 / +0 | 16 | 720ms | 5발 | 6발 |
| Lv.10 / +5 | 20.5 | 약 563ms | 4발 | 5발 |
| Lv.30 / +20 | 32.25 | 약 364ms | 3발 | 3발 |

횟수는 정상 체력에서 플레이어 발사체만 맞는 경우다. NPC에게 이미 다친 대상은 더 적은 발수로 쓰러질 수 있다. 레벨·강화·인벤토리와 저장 형식은 유지하며 현재 저장 파일을 직접 수정하지 않았다.

보스 체력은 기존처럼 봉인 해제 시 DPS 약 10초분으로 정하되 상한을 900으로 맞춘다. 예전 공격력으로 산정된 큰 보스 체력이 저장돼 있으면 로드 시 900 이하로 정규화한다. 챕터 진행 비트는 유지하므로 봉헌·완료 보상을 다시 발생시키지 않는다.

## 확인 범위

소스의 실제 피해·간격 식을 추출해 유효한 성장 조합 630개에서 피해 양수·성장 단조 증가·최소 3발·연사 하한을 확인했다. Bloom 가중치 합과 픽셀 샘플링 유지도 확인했다. 기존 --self-test에 성장 범위, 강화 효과, 구 보스 저장 호환 및 재저장 검사를 추가했다.

사용자 요청에 따라 이번 변경은 빌드·게임 실행·렌더링 결과 확인을 하지 않았다. 아래는 사용자 빌드 후 실행할 선택적 검사다. 기존 폴더를 재사용하지 말고 새 절대 경로를 지정한다.

```powershell
.\SimpleGame.exe --self-test C:\Temp\Ashen-ClarityCombat-Check-New
```

기존 GLFW/STUTTER 검증 JSON은 당시 코드·설정의 기록이다. 이번 변경은 의도적으로 화면과 전투 수치를 바꾸므로 그 기록의 화면 해시나 수치를 새 버전의 결과로 간주하지 않는다.
