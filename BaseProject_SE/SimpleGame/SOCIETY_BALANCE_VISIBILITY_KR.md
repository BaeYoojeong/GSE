## 문제와 변경

상인은 거래 가능한 NPC가 없으면 거래 점수가 비활성화되어 시장을 떠났다. 주민 사냥은 사냥터의 체력 수치를 바꾸는 방식이었고, 공격 표시는 짧은 자세 변화뿐이었다. 일반 몬스터를 공격하는 주민도 수호 성향 전승자로 제한되어 있었다. 각 청크의 일반 몬스터 두 마리와 거점의 사냥터 네 마리가 별도로 생성되어 마을에는 여섯 마리가 배치될 수 있었다.

### 상인

- 마을의 생존·비적대 상인이 60초 단위로 시장 근무를 교대한다. 다음 근무자는 교대 10초 전부터 거래에 높은 가중치를 받는다. 중상·부활 보호 상태에서는 회복이 우선이다.
- 근무 중에는 현재 NPC 거래 상대가 없어도 손님을 기다리는 거래 행동을 선택한다. 비근무 상인의 사냥·학습·휴식·약탈 전이는 유지한다.
- 거래 목적지는 좌우 노점 앞이다. 금빛 모자와 가방, 동전 표식으로 상인을 구분한다. 표식 아래 녹색 선은 광장에 있는 비적대 상인을 뜻하며 재고나 잔액을 보장하는 표시는 아니다.
- 대화창이 닫혀 있을 때 B/N은 가까운 상인을 찾는다. 모닥불이나 다른 직업 주민이 더 가까워도 거래 대상 선정에 끼어들지 않는다. 열린 대화의 대상은 그대로 존중한다.
- 재고와 돈을 자동으로 보충하지 않는다. 실제 주민 간 거래, 사냥, 플레이어 거래가 경제에 반영된다.

### 주민 전투

| 항목 | 이전 | 변경 |
|---|---|---|
| 사냥꾼 기본 피해량 | 15 | 30 |
| 사냥꾼 공격 간격 | 1.1초 | 0.8초 |
| 다른 주민 기본 사냥 피해량 | 15 | 22 |
| 다른 주민 공격 간격 | 1.1초 | 1.1초 |
| 일반 몬스터 대응 | 수호 전승자만 | 사냥꾼 165, 다른 주민 100 거리 안의 가까운 일반 몬스터 |
| 사냥터 전투 | 45 거리 이내 접근 | 약 68 거리의 분리된 사격 지점, 최대 95 거리·시야 확인 |
| 공격 표현 | 행동/쿨타임에서 추정한 자세 | 실제 공격 방향·자세, 0.45초 픽셀 궤적, 타격 십자, 피격 섬광 |

피해량에 깨달음/25만큼 보정하되 추가 피해는 최대 8이다. 체력 60인 사냥터 몬스터는 기본 사냥꾼이 두 번, 다른 주민이 세 번 공격하면 처치할 수 있다. 실제 타격 간격은 10Hz 시뮬레이션 갱신 단위에 맞춰진다.

일반 몬스터 대응·사냥·약탈은 같은 공격 쿨타임을 공유한다. 중상·부활 보호·플레이어 적대 상태에서는 일반 몬스터 방어가 기존 회복과 보복을 가로채지 않는다. 주민 간 약탈 피해도 직업별 피해량을 사용하고, 피해 주민의 반격은 쿨타임이 준비되었을 때만 발생한다. 플레이어에 대한 주민의 보복 피해는 12에서 18로 조정했다.

주민이 일반 몬스터를 처치하면 주민에게 물자·동전·깨달음을 지급한다. 플레이어에게 경험치나 물자를 자동 지급하거나 같은 처치 보상을 바닥에 중복 생성하지 않는다. 플레이어가 직접 처치했을 때의 경험치·드롭은 유지한다.

픽셀 궤적은 실제로 처리된 즉시 공격을 보여 주는 표시다. 별도의 물리 발사체 충돌 판정을 추가한 것은 아니다. 로딩된 일반 몬스터의 목록은 시뮬레이션 틱마다 한 번 수집하고 모든 주민이 재사용한다.

### 몬스터 밀도와 리젠

- 기본 세 마을은 사냥터 두 마리만 배치한다. 사냥터는 광장에서 볼 수 있는 남쪽의 서로 떨어진 두 구역에 배치한다.
- 다른 청크의 일반 몬스터는 최대 한 마리다. 시드로 결정되는 청크의 약 1/3은 일반 몬스터가 없는 구역으로 둔다.
- 사냥터 리젠 간격은 2→6초, 일반 몬스터는 5→12초다. 기존 사냥터의 분산·점유 검사와 슬롯당 Actor 중복 방지는 유지한다.
- 일반 몬스터 리젠 지점에 플레이어가 120 거리 안에 있거나 같은 지역 주민이 90 거리 안에 있으면 1초 후 다시 시도한다.
- 생성, 리젠, HTML 모니터의 알려진 몬스터 수, 콘솔의 슬롯 상한이 동일한 `EnemySlotEnabled` 규칙을 쓴다.

## 저장 호환성과 렌더링

기존 `SOCIETY_V1/V2`를 읽는다. V2에 저장된 사냥터 네 슬롯을 먼저 검증한 후 폐지된 2·3번 슬롯만 제거하고, 주민·전승·경제·사망 횟수를 유지한다. 다음 저장에는 두 슬롯을 기록한다. 일반 몬스터의 기존 두 슬롯 저장 비트는 유지하면서 생성 가능한 슬롯만 선택한다. 세이브 초기화나 삭제는 필요하지 않다.

주민 공격/피격 표시는 런타임 관찰 정보이며 세이브 포맷에 추가하지 않는다. 상인·사냥꾼·약탈자의 새 모델은 기존 캐시를 재사용하지 않도록 주민 메시 키의 리비전을 올렸다. 공격 궤적과 동전 표식은 캐시된 단위 사각형의 인스턴스이며 매 프레임 새 메시를 생성하지 않는다. HDR/Bloom 파이프라인을 그대로 사용한다.

## 분석 로그

10초마다 기존 `society_summary` 프로파일러 기록 및 `[society_combat]` 콘솔 출력에 아래 필드가 포함된다.

- `merchants`: 생존 상인 수.
- `merchants_at_market`: 광장에 있는 비적대 생존 상인 수.
- `npc_attacks_10s`: 최근 보고 구간에 실행된 주민 공격·약탈·반격 횟수.
- `npc_monster_kills_10s`: 같은 구간 주민의 사냥터/일반 몬스터 처치 수.

누적 사냥·거래·약탈과 시뮬레이션 CPU 시간도 함께 남는다. `population_spacing`의 `enemy_slot_limit`은 현재 로딩 청크에 실제 허용된 일반 몬스터 슬롯 수를 뜻한다. 프레임별 출력은 추가하지 않았다.

## 확인 범위

소스 흐름, 저장 필드 검증, 메시 캐시 키, 생성/리젠/모니터의 공통 개체 수 규칙을 정적으로 확인한다. 요청에 따라 빌드·게임 실행·화면 확인은 사용자에게 남긴다. 아래 항목은 실행 결과가 아니라 수동 확인 항목이다.

1. 기존 세이브로 재실행해 주민·경제·전승 정보가 유지되는지 확인한다.
2. 시작 마을의 노점 앞에서 금빛 상인과 동전 표식을 찾고 B/N 거래를 확인한다.
3. 60초 교대 전후 상인이 복귀하는지, 빈손님 상태에서도 근무자가 시장에 남는지 확인한다.
4. 남쪽 두 사냥터에서 주민의 발사 방향·타격·체력 감소와 처치를 확인한다.
5. NPC 처치로 플레이어 경험치가 증가하지 않는지 확인한다.
6. HTML 모니터와 `population_spacing` 로그의 몬스터 수가 생성 규칙과 일치하는지 확인한다.
7. 리젠 지점을 점유했을 때 플레이어나 주민 위에 일반 몬스터가 나타나지 않는지 확인한다.
