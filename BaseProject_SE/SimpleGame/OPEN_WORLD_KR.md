# 오픈월드 탐험과 동적 지도

## 기존 구조에서 작게 느껴진 이유

플레이어 이동에는 일곱 마을의 경계를 기준으로 막는 벽이 없었다. 정수 64비트 청크 좌표와 작은 로컬 좌표를 사용하고, 이동한 청크를 중심으로 5×5 구역을 스트리밍하는 구조다. `PlanetWorld`의 행성 구분도 이동 제한이 아니라 좌표의 분류다. 다만 지도 이미지는 일곱 마을 주변의 고정 사각형이었으며, 청크마다 다른 바이옴·십자 도로·중앙 모닥불이 반복되어 작은 구역을 반복하는 느낌을 주었다.

## 이번 변경

### 이동·확대 가능한 이미지 지도

- **M**: 플레이어 위치를 중심으로 지도 열기. 이전 확대 배율은 유지한다.
- **왼쪽 드래그**: 지도 이동. 기존 일곱 마을 지도 경계에서 멈추지 않는다.
- **휠**: 커서가 가리키는 월드 지점을 유지하며 확대/축소한다.
- **F**: 현재 위치로 중심 이동.
- **G**: 일곱 마을 개요로 돌아가기.
- **1~7**: 해당 포탈을 선택하고 지도 중심 이동. **0**: 선택 해제.
- 포탈 클릭: 선택. 이동 버튼 / **Enter**: 이미 활성화한 포탈로 이동.
- **M / Esc**: 지도 닫기. 지도 드래그를 포탈 클릭으로 처리하지 않는다.

`WorldMap::View`는 정수 청크 중심·로컬 좌표·청크당 픽셀 수를 가진다. 먼 좌표의 차이는 정수로 먼저 계산한다. 따라서 2^59 정도의 큰 좌표에서도 바로 옆 청크가 같은 위치로 뭉개지지 않는다. 지도는 세계 전체를 거대한 텍스처로 만들지 않고, 현재 보이는 520×390 픽셀만 생성한다. 최소 배율에서도 분류할 청크는 약 3,400개 이하로 제한된다. 지도 미리보기는 `RegionAt`이나 NPC 생성을 호출하지 않는다.

주민 집은 실제 홈 좌표에서 표시한다. 보기 위치·배율·월드 시드·집 배치가 바뀐 경우에만 GPU 이미지를 갱신하며, 드래그 중에는 기존 이미지를 이동시켜 재사용한다. 드래그를 놓은 뒤 또는 확대 시 최대 120ms 간격으로 갱신한다. 이미지와 표식은 프레임버퍼 뷰포트를 기준으로 scissor 처리하여 옆 패널을 덮지 않는다. 고해상도 배율·레터박스 변환을 마우스 클릭·이동·휠에서 함께 사용한다. 창 포커스를 잃거나 화면 밖에서 버튼을 놓으면 드래그를 해제한다.

### 넓게 이어지는 변경

`WorldLayout`의 순수 함수들이 게임 지형과 지도에 같은 분류 규칙을 제공한다.

| 요소 | 동작 |
|---|---|
| 바이옴 | 8청크 단위 격자의 값을 보간하여 황혼 수림·안개 습지·잿빛 황무지가 여러 청크에 이어진다. |
| 도로 | 마을의 기존 도로를 유지하고, 외곽 주요 도로는 4청크 간격으로 놓는다. |
| 야영지 | 6×6 청크 구역마다 절차적으로 배치한 천막·모닥불. 물자로 불씨를 되살리고 휴식·체크포인트로 사용한다. |
| 폐허 | 외곽에서도 반복 생성되는 무너진 돌기둥과 기록. E로 세계관의 흔적을 읽는다. |
| 약초 군락 | 외곽 채집 구역을 알려주는 식생 표식. 주변의 기존 6개 채집 슬롯을 이용하며 중복 보상을 추가하지 않는다. |

각 6×6 구역에는 세 종류의 지점을 서로 다른 청크에 결정적으로 배치한다. 마을과 챕터의 주요 장소에서는 기존 콘텐츠를 우선한다. 일부 추가 작은 모닥불도 존재한다. 주황·보라·초록의 지도 점은 각각 절차적 야영지·폐허·약초 군락을 표시한다. 충분히 확대하면 이름을 표시한다. 표식은 탐험 후보를 보여주는 지형 정보이며 방문 여부를 기록하는 시스템은 이번 범위에 포함하지 않는다.

탐험 오브젝트는 `ExplorationActor`로 SceneGraph에서 관리하며 세 종류의 메시를 MeshCache/디스크 캐시에서 공유한다. 지형 메시 키의 버전을 4로 올리고 도로·캠프 배치 비트를 포함하여 이전 지형 메시를 재사용하지 않게 했다. 매 프레임 새 탐험 메시를 만들지 않는다.

장애물의 기존 안전 간격·청크 가장자리·십자 통행 공간·남쪽 채집 공간은 유지한다. 시각적으로 도로가 없는 청크에서도 이 통행 공간은 이동할 수 있다. 새 탐험 오브젝트는 충돌 벽을 만들지 않는다.

## 기존 기록과 규모

- 마을은 기존 **7개**, 초기 주민은 **210명**이다. 외곽 생성이 주민 수를 무제한 늘리지 않는다. 주민이 거주하는 신규 도시를 무한 생성하는 기능은 이번 변경에 포함하지 않는다.
- 이미 밝힌 모닥불과 현재 체크포인트는 새 캠프 배치에 없더라도 계속 생성한다.
- 채집·적·드롭의 슬롯, 사망 전승, 챕터, 인벤토리, 포탈 활성화 저장은 유지한다. 저장 버전은 V8 그대로다. 기존 지역의 시각적 지형은 새 규칙으로 바뀐다.
- 이동 범위는 일곱 마을과 독립적이다. 수학적인 무한 정밀도는 아니며, 기존 저장 형식의 64비트 청크 안전 범위를 사용한다. 화면 주변 25개 청크와 기존 SQLite 지역 기록·캐시 관리 구조를 유지한다.

## 분석과 확인

`world_chunk_generated` 로그에 실제 생성된 청크의 x/y, 바이옴, 탐험 지점 종류를 기록한다. `chunk_stream`은 기존 스트리밍 시간 측정을 유지한다. `world_map_image`는 이미지 갱신 시에만 바이트 수·갱신 시간을 기록한다. 드래그 중·지도가 가만히 있는 동안에는 이 갱신 로그가 매 프레임 쌓이지 않는다. 지속 이동 시 `world_chunk_generated`의 좌표가 기존 마을 영역을 벗어나 계속 바뀌는지 확인할 수 있다.

사용자 요청대로 빌드·게임 실행·렌더링 결과 확인은 수행하지 않았다. 소스 구조, 프로젝트 등록, 메시 키, 좌표 연산과 입력 경로를 정적으로 확인했다. 선택적 `--self-test`에 큰 좌표에서의 지도 투영·커서 중심 확대·드래그/클릭 구분·지도 미리보기의 상태 비변경·외곽 청크 이동·25청크 제한·탐험 지점 통행 검사를 추가했다. 추가한 C++ 검사는 실행 전 상태다. 성능 개선 수치는 실제 사용자 빌드의 프로파일 로그로 측정해야 한다.
