# 야외 활동·몬스터 비율·약탈 관찰 개선

작성일: 2026-10-14. 이전 `WORLD_ACTIVITY_ROUTES_KR.md`의 밀도·이동·저장 버전 설명을 갱신하는 후속 보고서다.

## 기존 실행에서 확인한 사실

게임을 새로 실행하지 않고 기존 `World_v1.txt`와 프로파일러 CSV를 읽었다.

- 저장된 시뮬레이션 시간 약 990.9초에서 주민 19명, 누적 약탈 113회, 사냥 855회, 거래 135회였다. 누적 수는 이전 실행도 포함한다.
- `2026-10-14_13-5-16-442_37224/events-0.csv`에 NPC 15 → 13, 9 → 7, 3 → 14가 각각 동전 6개를 이전한 `event=raid` 기록이 있었다.
- 약 983.1초 보고에서는 외출 주민 6명, 일반 몬스터 Actor 32개, 사냥감 Actor 12개였다. 이는 로딩된 여러 청크의 합계이며 플레이어 화면 안에서 보이는 수와 다르다.
- 모든 청크에 집·예배당·돌 광장이 반복 배치되어 다른 청크로 이동해도 마을처럼 보였다.
- 사냥터 3곳 중 2곳이 소속 마을 안에 있고 가까운 사냥감으로 목표를 다시 선택하여 장거리 활동을 제한했다.
- 일반 몬스터 체력은 48이라 기본 피해 30인 사냥꾼에게 두 번 맞으면 사라졌다. 약탈 공격 표시는 짧고 성공 후 24초 대기하여 관찰하기 어려웠다.

## 몬스터 배치와 주민 이동

| 항목 | 이전 | 변경 |
|---|---|---|
| 일반 몬스터 슬롯 | 청크당 1~2개 | 청크당 2개 |
| 일반 몬스터 체력 | 48 | 72 |
| 일반 몬스터 기본 재생성 | 8초 | 6초 |
| 거점당 사냥터 | 3곳 | 6곳 |
| 소속 청크 밖 사냥터 | 1곳 | 5곳 |
| 새 사냥감/재생성 체력 | 60 | 90 |
| 사냥감 기본 재생성 | 4초 | 유지 |
| 약탈 성공 후 대기 | 24초 | 12초 |

일반 몬스터는 기존 2개 슬롯과 드롭/처치 비트를 쓴다. NPC 기록을 삭제하여 비율을 조정하지 않는다. 주민 수, 즉시 부활, 전승, 재산을 유지한다. 슬롯은 배치 용량이며 점유 검사와 재생성 대기로 실제 생존 수는 더 적을 수 있다.

사냥터 중심은 소속 마을 기준 `(210,570)`, `(1110,410)`, `(-180,570)`, `(380,-180)`, `(168,1388)`, `(1368,1338)`이다. 각각 소속 마을 외곽, 동·서·북·남·남동쪽 이웃에 해당하며 중심 주변의 ±24 후보에 배치한다. 이웃 청크에 다른 마을이 있으면 그 마을 외곽의 사냥터가 된다. 소속 밖이라는 사실과 실제 야외라는 사실을 별도 집계한다.

살아 있고 예약 가능한 사냥감은 이동 중 유지한다. 새 사냥감은 주민 ID와 사냥 완료 횟수로 선호 구역을 순환한다. 구역별 동시 예약 상한은 2명이다. 대상 사망·점유 등으로 선택할 수 없으면 다른 대상을 찾는다.

새 목적지는 거리와 속도에 따라 10~45초 동안 유지한다. 일반 점수 변동만으로 되돌아가지 않으며 체력이 55% 이하가 되거나 부활 보호·사냥 불가·당번 교대가 발생하면 재평가한다. 도착하면 유지 시간을 해제하고 로그를 남긴다. 상한 시간은 목적지가 영구 고정되는 것을 막는 장치이며 충돌 무시나 순간이동은 하지 않는다.

수련은 이웃 지역 명소와 알려진 마을 방문을 번갈아 선택한다. 이동 중 몬스터 방어가 기존 사냥 예약·약탈 추적 대상을 지우지 않는다. 사냥 의도가 아닌 주민의 자동 방어 거리는 65로 제한한다. 개인 활동 범위는 기존처럼 소속 마을 중심 3×3 청크다.

## 마을과 야외의 외관

집·예배당·상점·돌 광장은 실제 거점에만 배치한다. 야외는 흙길과 작은 모닥불 쉼터를 사용한다. 충돌 없는 도로 공간과 기존 체크포인트는 유지한다.

전승자가 야외에 새 거점을 만들면 이미 로딩된 청크에도 중복 없이 구조물을 추가하고 충돌 목록을 갱신한다. 지면 메시 캐시 키에 거점 여부와 새 지면 버전을 포함하여 이전 광장 메시가 야외에 재사용되지 않게 한다. 기존 메시 캐싱/배칭 구조를 유지한다.

## 약탈 동작과 표시

약탈 대상은 활동 범위 안의 재산·거리·외출 여부를 비교해 정한다. 유효한 추적 대상은 400단위 밖으로 나가도 유지한다. 약탈 성향이 0.6 이상인 주민은 대상이 없으면 야외 도로를 순찰하며 찾는다. 다른 직업도 기존 가중치에 따라 약탈할 수 있다.

실제 강탈은 기존 근거리/장애물 조건을 통과해야 한다. NPC에게서 한 번에 최대 6개, 플레이어에게서 최대 3개의 동전을 이전하며 잔고와 소지 한도를 지킨다. 타격·반격·사망·재산 이전·즉시 부활 규칙도 유지한다.

- 탐색/추적 중: 주민 옆 붉은 느낌표.
- 실제 동전 이전 성공 후: 4초 동안 금색 동전 표시.
- 모니터: 야외 대상 탐색, 약탈 대상 추적, 약탈 성공, 재약탈 대기, 플레이어와 교전, 다른 활동 중을 구분.
- 주민 상세: 이번 실행의 성공 횟수·강탈 동전 합계·최근 대상/금액·다음 약탈까지의 시간.

`intention=raid`는 의도이며 성공을 뜻하지 않는다. 양수의 동전이 실제 이전될 때만 성공 수를 증가시킨다. 대기 시간에는 다른 활동을 할 수 있다.

## JSON과 분석 로그

추가 NPC 필드는 `raid_phase_label`, `raid_cooldown_seconds`, `successful_raids_session`, `stolen_coins_session`, `last_raid_target`, `last_raid_amount`, `travel_commit_seconds`, `destinations_reached_session`, `in_wilderness`다. 큰 정수 카운터와 대상 ID는 문자열이다. 최근 금액 0은 이번 실행 기록 없음, 대상 ID 0은 플레이어다.

모든 `_session` 필드는 재실행 시 초기화되는 관찰 정보로 상단 누적 약탈 수와 의미가 다르다. `destination_kind=patrol`은 대상 미정 상태의 야외 탐색 목적지다.

| 로그 | 용도 |
|---|---|
| `society_destination` | 실제 목적지와 이동 유지 시간 |
| `society_arrival` | 주민 ID와 도착한 여행 번호 |
| `raid_pursuit` | 새로 추적하기 시작한 주민 ID |
| `raid_transfer` | 실제 이전 금액과 이전 후 양측 동전 잔고 |
| 기존 `society`의 `raid` / `rob_player` | 시각·공격자·피해자·사건 위치·금액 |
| `society_summary` | `wilderness_residents`, `raid_pursuit`, `raid_search`, `committed_trips`, `successful_raids_10s` |
| `population_spacing` | 로딩된 몬스터·주민, 슬롯 상한, 중복, 점유 대기 |

## 저장과 확인 범위

새 사회 저장은 `SOCIETY_V4`이며 V1/V2/V3도 읽는다. 기존 NPC 좌표·재산·사망 횟수를 보존하고 사냥터를 6곳으로 확장한다. 기존 살아 있는 사냥감은 남은 체력을 유지하고 다음 재생성부터 90을 적용한다. 새 슬롯은 체력 90이다. 이전 일반 몬스터 최대 12초 대기는 현재 최대 6초로 제한한다. 관찰용 필드는 저장하지 않는다.

사용자의 저장 파일은 직접 수정하거나 삭제하지 않는다. 빌드·게임 실행·렌더링 확인은 사용자 담당이다. 기존 실행 로그를 읽은 것과 수정한 게임을 실행하여 검증한 것은 다르다. 이번 작업에서는 소스 검토, C++ 형식, 프로젝트 XML/파일 등록, 모니터 JS 구문을 정적으로 검사한다.

사용자 실행 확인:

- [ ] 이전 저장에서 주민 수·재산이 유지되고 사냥터가 거점당 6곳인지 확인.
- [ ] 야외에 집·예배당·광장이 반복되지 않고 실제 마을에는 유지되는지 확인.
- [ ] 사냥 목적지가 이웃 청크로 정해지고 도착 전에 계속 바뀌지 않는지 확인.
- [ ] 점유되지 않은 사냥터에서 4초, 일반 몬스터에서 6초 이후 재생성이 이어지는지 확인.
- [ ] 약탈 추적 후 금액 이전·금색 표시·모니터 성공 수 증가를 함께 확인.
- [ ] 새 전승 거점, 왕복 스트리밍, 저장/로드 후 표시 Actor가 중복되지 않는지 확인.
- [ ] 장시간 플레이에서 야외 주민 수·목적지 도착·약탈 성공 로그와 CPU 비용을 비교.
